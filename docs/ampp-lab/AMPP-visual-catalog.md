# 歌词背景视觉 · 可用方案总览（设计稿 v1）

> 2026-11-13 ｜ 状态：**方案选型，未改设备**
> 关联：`AMPP-visual-routes.md`（可行性/路线）、`AMPP-audio-beat-routes.md`（音频）、`AMPP-glow-layer.md`（现实现）
> LyricsBlossom 的 shader 级拆解仍在进行，其结论会补进第 5 节；本文件先给"有哪些方案可选、各自长什么样、代价多少"。

## 0. 选型的三个硬约束

1. **我们是加在宿主模糊封面之上的光**，不是替换背景。所以所有方案都必须是**加色/发光**语义（`PLUS`/`SCREEN`），
   一旦画不透明色块，就会和宿主底图打架，也会盖住歌词层的空间感。
2. **不能假设有音频**。默认能量源只有：帧时间、换行事件、逐词事件、播放位置、封面颜色。
   音频是可选增强（R3），方案必须在"无音频"时也成立。
3. **成本 = 填充像素数**。全屏 shader 最贵；圆形/带状局部填充便宜；粒子最便宜。

## 1. 方案清单（10 个）

按"推荐度"排序。每项给出：视觉、数据、实现要点、成本、风险。

### S1 · 边缘氛围光（现方案的改良版）
- 视觉：屏幕四边 3–5 团不同色相的柔光缓慢漂移，换行时整体轻抬一次
- 数据：时间 + 换行
- 实现：径向渐变圆 + `PLUS`；漂移用 2D value-noise，周期 25–40 s
- 成本：≈0.8 屏/帧；风险：低（现有代码改造）
- 评价：**保底档**。已经把"漏光感"压到最小，但仍然只是亮暗变化

### S2 · 流体极光（备选皮肤）
- 视觉：6 团大小不一的光体在封面背后缓慢翻涌，边缘被噪声"啃"出不规则轮廓
- 数据：时间 + 换行（强）+ 逐词（弱、局部）
- 实现：6 个径向渐变（PLUS）→ 硬件层内用 `DST_IN` 铺一张缓慢平移的 fBm 噪声
- 成本：≈2.5 屏/帧；风险：中（`LAYER_TYPE_HARDWARE` + blend，需实机验收）
- 评价：视觉最"躁"，但和 LyricsBlossom 的路子不同（它是平滑网格渐变）；作为可选皮肤保留

### S3 · 极光幕帘
- 视觉：从屏幕底部升起的几条竖直光幕，像极光帘，横向被噪声扰动，顶部渐隐
- 数据：时间 + 换行（高度/亮度）
- 实现：5–8 条贝塞尔带（`Path` + `LinearGradient` 竖直），每条 x 位移由低频噪声驱动
- 成本：≈1 屏/帧；风险：中低（形状要调，容易"塑料感"）
- 评价：很有辨识度，适合竖屏；横屏双栏时可能显得偏左/偏右

### S4 · 体积光柱
- 视觉：从封面向外放射的柔和光束，缓慢旋转，换行时亮度抬升
- 数据：时间 + 换行
- 实现：12–20 个细长扇形（径向渐变 + 旋转），`PLUS`
- 成本：≈1 屏/帧；风险：中（光束太硬会像"探照灯"）
- 评价：与封面位置强相关，双栏左对齐时好看

### S5 · 星尘粒子
- 视觉：几十到几百颗微光粒子缓慢上浮，3 层视差、各自闪烁；逐词时在局部炸开一小簇
- 数据：时间 + 逐词（关键）
- 实现：`drawCircle` 小半径（1–3 px）+ 预计算的伪随机序列，避免每帧分配
- 成本：≈0.2 屏/帧；风险：低
- 评价：**便宜且"活"**，很适合和 S2 叠加；单独用会显得单薄

### S6 · 液态波纹
- 视觉：换行时从封面扩散出一圈柔和涟漪，2–3 圈叠加衰减
- 数据：换行
- 实现：圆环描边 + 径向渐变 alpha，半径随时间扩张、alpha 衰减
- 成本：极低；风险：低
- 评价：作为**点缀**很好，做主视觉会重复感强

### S7 · 光谱环（需要音频）
- 视觉：围绕封面的一圈极坐标频谱，低频在左、高频在右，随鼓点起伏
- 数据：**真实 FFT**（R3）
- 实现：64–96 段极坐标条，半径 = 基准 + 频带能量
- 成本：低；风险：中（必须先有音频链路）
- 评价：没有音频时只能做"假频谱"，观感会露馅，建议放到 R3

### S8 · 网格渐变（推荐主攻，LyricsBlossom 同款思路）
- 视觉：4 个大色块在四角，边界用噪声缓慢变形，像 Apple 的"专辑取色背景"
- 数据：时间 + 封面调色板
- 实现：4 个超大径向渐变（半径 0.9E）+ `SCREEN`，色心位置由低频噪声漂移
- 成本：≈1.5 屏/帧；风险：低
- 评价：**拆解证实这就是 LyricsBlossom 的做法**（`BackdropMeshLayer` + `GradientCS`），
  成本比 S2 低一个数量级，作为默认主视觉

### S9 · 胶片颗粒 + 柔光
- 视觉：整屏极淡的颗粒，封面边缘有一圈柔光溢出
- 数据：无（静态）
- 实现：4×4 噪声平铺（alpha 3–5%）+ 柔光层
- 成本：≈1 屏/帧；风险：极低
- 评价：**万能调味**，让任何方案都"不那么像 UI"

### S10 · 视差星云
- 视觉：2–3 团巨大的星云 + 稀疏星点，整体极缓慢旋转
- 数据：时间 + 换行
- 实现：S2 的噪声遮罩 + S5 的星点 + 轻微旋转
- 成本：≈2 屏/帧；风险：中
- 评价：适合纯音乐/氛围曲，流行歌可能显得"太空"

## 3. 推荐组合（按拆解结论重排）

- **风格 A「封面渐变」（默认，主推）** = S8 网格渐变 + S9 dither
  → 直接复刻 LyricsBlossom 的背景做法；成本 < 1 屏/帧；平滑、不刺眼、和封面天然同色
- **风格 B「渐变 + 星尘」** = A + S5 粒子（少量、慢速）
  → 加一点"活"，但粒子要克制（他们没做粒子，做多了会廉价）
- **风格 C「极简边缘光」** = 现方案改良（S1）
  → 保底/省电档
- **风格 D「音频增强」** = A + 真频带（R3）
  → 频带只调渐变的对比/速度，**不做鼓点闪烁**

S2 流体极光从"主攻"降级为**可选皮肤**：它和 LyricsBlossom 的路子不同（噪声啃边、翻涌感更强），
如果哪天想要更"躁"的风格再上，不作为默认。

## 4. 架构（一次做对，后面只加 style）

```kotlin
interface LyricGlowStyle {
    val id: String
    fun draw(canvas: Canvas, frame: GlowFrame)
}

data class GlowFrame(
    val nowMs: Long,
    val width: Int, val height: Int,
    val palette: List<Int>,        // 封面 4 色
    val coverLuma: Float,          // 0..1，用于亮度自适应
    val energy: Float,             // 全局能量（换行脉冲）
    val hits: List<GlowHit>,       // 局部脉冲（逐词/换行），带归一化坐标
    val beatPhase: Float,          // 0..1，无音频时由时间+行事件估计
)
```

引擎负责：调色板提取、噪声表、能量源、帧率控制、dither、生命周期（现有 `attach/watcher` 可复用）。
`GlowLayer` 只保留"挂载 + 帧循环 + 设置读取"，绘制全部下沉到 style。

## 5. LyricsBlossom 到底靠什么好看（已拆完，结论和直觉相反）

子代理把 146 MB 包（含 57 MB `libmain.so`）拆完之后，结论是：**它没有粒子、没有 bloom、
没有反馈拖尾、没有频谱、没有 BPM 检测**——这些词在二进制里只出现在第三方库里
（SQLite `CREATE BLOOM FILTER`、DNG `FixVignetteRadial`、HEVC `chromaticities`）。

它真正的背景是一条**封面网格渐变**（RTTI 类名 `BackdropMeshLayer`）：

| 事实 | 证据 |
|---|---|
| 背景 = ≤24×24 控制网格，格子尺寸按 `screenW/645`、`screenH/1365` 取整并夹到 ≤24 | `0x29C45E0-0x29C46A8` |
| 网格颜色由 compute 程序 `GradientCS` 从封面纹理算出来 | 字符串 `GradientCS` @`0x1AC0A8`，非 Skia 内置 |
| 网格不可用时退化成 `Backdrop.BroadBlur`（大范围模糊） | 字符串 @`0x1CAAE8` |
| 有 `OrderedDitherEffect` 专门去色带 | RTTI |
| 没有 CPU 调色板提取（无 k-means / median-cut / oklab / histogram） | 全库字符串检索为空 |
| 音频帧 48k 立体声 → 单声道、2048 窗、1024 hop（21.33 ms）、AGC(0.3/0.01)、6 个对数频带 + 4 个标量、32 帧历史 | §1.4–1.5 |
| **没有 onset/beat/tempo 检测**，TBPM 只是 ID3 标签名 | §1.6 |
| 后处理：只有 Skia 的 SkSL 内置 + 加密的 52 个 `CRShaderProgram`（AES-256-GCM，密钥在运行时推导） | §3 |

层序（后→前）：**网格渐变背景 → 动态封面 → 歌词 → 播放器控件 → 液体玻璃浮层**。

### 5.1 这对我们意味着什么

1. **好看的不是"特效"，是"平滑"**：一条由封面派生、几乎不动的超大渐变，
   加上真实的动态封面和玻璃 UI，整体就像"活的"。我们的眩光感来自"边缘光"这种硬形状，方向就错了。
2. **音频不是用来闪的**：没有 beat 检测，只有平滑的频带能量，用来缓慢改变渐变的颜色/对比。
   这解释了它为什么不刺眼——**它根本不是跟着鼓点跳**。
3. **动态封面抄不了**（要 Apple 令牌 + 自己解码视频），但**网格渐变可以 1:1 复刻**，
   而且代价极低（见 5.2）。

### 5.2 复刻配方（这就是我们要做的东西）

```
输入：封面 64×64（现有 capture hook 提到 64 就够）
1) 取 8×5（横屏）/ 5×8（竖屏）个采样色 —— 直接对应他们 screenW/645 的思路，格子很少
2) 每个格子加轻微时间扰动（低频噪声，幅度 ~8% 色相/亮度）
3) 生成 8×5 的 Bitmap，drawBitmap(dst=全屏, FILTER_BITMAP) 双线性放大
4) 一层轻模糊（RenderEffect ~12–20 px）把双线性的菱形抹平
5) OrderedDither：4×4 噪声，alpha 3–5%
6) 能量：换行 → 全局对比/亮度 +8%；逐词 → 该格局部 +3%
```

成本：**每帧一次小位图上传 + 一次全屏 blit**，比现在的边缘光环还便宜（光环是整屏 bitmap shader）。
没有渐变叠加以外的额外 pass，30–60 fps 都轻松。

## 6. 我们还能借用的现成资产

| 资产 | 位置 | 能用来干什么 |
|---|---|---|
| Kyant `backdrop` AGSL 库（已 vendored） | `AM-plus-plus/backdrop/` | 现成的 AGSL 基础设施：`RuntimeShaderCache`、圆角 SDF、折射/模糊/镜头 shader；写流体 shader 时不用自己搭轮子 |
| 宿主的动态封面视图 | 播放页 `fullplayerSongImage/video_surface`（TextureView） | 理论上可 2–4 fps `getBitmap()` 采样后重度模糊做底图动效；**成本高**，列为实验项 |
| 逐词高亮事件 | `AppleMusicLyricBlurRuntime` 已在跑 | 免费的高频能量源，密度足够撑起"逐词微脉冲" |
| 封面 32×32 → 可提到 128×128 | `BackgroundPulse` capture hook | 调色板提取质量直接决定观感 |
