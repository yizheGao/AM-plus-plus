# 歌词背景视觉：拆解 LyricsBlossom 与我们的复刻路线（研究稿）

> ⚠️ 拆解完成后结论有变：LyricsBlossom 的背景其实是**封面网格渐变**，不是流体噪声/粒子。
> 主推方案请以 `AMPP-visual-catalog.md` 第 3、5 节为准；本文件保留作为可行性与边界分析。

> 时间：2026-11-13 ｜ 状态：**只做研究，不动平板上的版本**
> 前置：`AMPP-insertion-scan.md`（夹层位置结论）、`AMPP-audio-beat-routes.md`（音频路线评估）、`AMPP-glow-layer.md`（当前光环实现）

## 0. 为什么现在这套不好看

现在的实现是「贴边一圈距离场光环 + 缓慢呼吸 + 换行脉冲」：

- **只有亮度和位置在动**，没有颜色层次、没有形状变化 → 看起来像屏幕边缘漏光，不像"有内容的光"；
- 形状是**解析距离场**，永远是最规整的一条带，没有任何有机感；
- 反应源只有"换行"一个，密度低（一首歌 3–6 秒才一次），大部分时间画面是"静止的呼吸"；
- 颜色只有封面主色一个色相，缺少双色/三色过渡。

要好看，需要补上四件事：**多色、有机形状、持续缓慢的运动、更密的能量源**。

## 1. 我们的夹层能做什么（已实测的边界）

```
player_root
  #0 background_layers   宿主模糊底图
  #1 GlowView            我们（z=0，可任意绘制）
  #2 …                   封面/歌词/控件（全在其上）
```

| 能力 | 结论 |
|---|---|
| 绘制 | 硬件加速 Canvas 全量可用；API 33+ 可用 AGSL `RuntimeShader`（可作 Paint 的 Shader） |
| 混合 | `BlendMode.PLUS/SCREEN` 对上层透明叠加，光感好 |
| 尺寸 | 3008×1880 / 1880×3008，全屏 View |
| 触摸 | 不可点，事件穿透（已验证） |
| 数据 | 封面位图（现 32×32，可提取到 64–128）、逐行时间、**逐词高亮事件**（`nativeWord` 已在 `AppleMusicLyricBlurRuntime` 的回调里流过，只是现在没用）、播放位置、seek |
| 音频 | 进程内 Java 抓不到 PCM（已证伪）；native 走 OpenSL ES |
| 性能基线 | 当前整屏 bitmap shader 20 fps：`gfxinfo` 0% janky、50th 14 ms |

关键：**绘制的代价取决于"被填充的像素数"，不是"画了几个元素"**。`drawCircle` 带径向渐变只填圆内，
所以"十几个大小不一的软光斑"比"一次全屏 shader"更便宜。

## 2. LyricsBlossom 的结构（先给结论级观察，详细拆解见 REPORT.md）

- 它不是 Java/Compose 画的：APK 里只有 1 个 1.1 MB 的 `classes.dex`，主体是
  `lib/arm64-v8a/libSDL3.so` + `libmain.so` → **SDL3 + 原生 GL 渲染**，Java 只是壳（权限、服务、MediaProjection、UI）。
- 音频走 **MediaProjection + AudioPlaybackCapture**（我们此前已记录它声明了 `RECORD_AUDIO` 与
  `FOREGROUND_SERVICE_MEDIA_PROJECTION`），再把能量/频谱喂给 native 渲染层。
- 所以它的"好看"来自两件事：**原生 shader 管线** + **真实音频能量**。我们需要判断：
  这两件事各自贡献多少，我们能不能分别替代。

## 3. 三条候选路线

### R1 · 极简呼吸光（改良现状，1–2 天）

保留"边缘光"的语义，但换成 3–5 个**不同色相、不同速度**的软光斑在边缘缓慢漂移，
换行时整组亮度轻微上抬。改动集中在 `GlowLayer` 的绘制与运动模型，风险最低。

- 视觉：像屏幕四角有彩色氛围灯在缓慢换气
- 优点：几乎零风险、性能已验证
- 缺点：仍然"只有亮暗"，跟现在的差距是量的差别，不是质的

### R2 · 流体极光 / 回馈光（推荐主攻，3–5 天）

把"环"换成**多层有机光团**：

1. **调色板**：封面 64×64 → 取 3–5 个主色（HSV 聚类），按亮度排序做主/辅色；
2. **光团**：6–8 个节点，位置由 2D value-noise 缓慢漂移（周期 20–40 s），半径 0.15–0.35 屏；
3. **叠加**：`BlendMode.PLUS` 叠加多层软径向渐变，中心偏暖白、外缘偏封面色 → 有"光源"感；
4. **拖尾**：保留前 5–8 帧节点状态、按 alpha 递减重绘（不建离屏缓冲，纯状态回放）；
5. **能量源**：逐行（强、全局）+ 逐词（弱、局部）双通道；attack 80 ms / decay 700–900 ms；
   逐词事件现成——`nativeWord` 回调已经在跑（`session.nativeEvent`），只需在里面多转发一次 `pulse(0.18f)`；
6. **去带状**：叠一张 4×4 noise 平铺、alpha 3–5% 的 dither 层，避免大面积渐变出现色阶；
7. **底图亮度自适应**：用封面 32×32 副本估算平均亮度，暗封面放大 alpha、亮封面收敛，
   避免"亮色专辑 + 强光"过曝；
8. **可选 AGSL 升级**：把"噪声 domain warp + 调色板查找"写成 RuntimeShader，作为
   **局部区域**的 Shader（不是全屏），只在光团范围内填充。

- 视觉：接近"极光/流体在封面背后缓慢翻涌，歌词换行时整体呼吸一次"
- 风险：大面积渐变的**色带**（用 dither 解决）、多光斑叠加的**过曝**（用 PLUS 前先降 alpha）
- 验收：`gfxinfo` 0–2% janky；与现版 A/B 截图；暂停时完全静止、退出页面无残留

### R3 · 真音频驱动（要"真的踩点"才做，1–2 周）

沿用 `AMPP-audio-beat-routes.md` 的结论，最短路径是**伴生 App**：

```
伴生 App（RECORD_AUDIO + MediaProjection）
  AudioPlaybackCapture → AudioRecord 44.1k/16bit/mono
    ├ RMS 包络（10 ms 帧）
    ├ 64-bin FFT → 低频/中频/高频三段能量
    └ 起音检测（局部均值 + k·std，refractory 180 ms）
  IPC：UDP 127.0.0.1 → {t, energy, band[3], beat, bpm}
        ↓
模块 GlowLayer：把 energy 当作 R2 的全局能量源，把 beat 当作脉冲源
```

- 视觉：R2 的形体 + 真实的鼓点/段落起伏
- 代价：多一个常驻 App、需要一次屏幕/音频捕获授权、前台服务通知
- 降级：IPC 超时自动退回"歌词 onset"驱动（R2 的默认源）

## 3.5 R2 的三个绘制手法（决定"像不像"的关键）

1. **软光团叠加**：`Paint.shader = RadialGradient(4 段 stop)` + `BlendMode.PLUS`，
   多团叠加天然产生"中心亮、外缘衰减"的体积感；只填圆内，成本与团数线性但不覆盖全屏。
2. **噪声切形（重点）**：给 `GlowView` 设 `LAYER_TYPE_HARDWARE`，让系统先把我们的内容渲进
   独立图层，再在图层内用 `BlendMode.DST_IN` 盖一张**平铺的 fBm 噪声位图**（256×256，
   缓慢平移 + 轻微缩放）——圆形的光团会被噪声"啃"出不规则边缘，得到极光的质感，
   而且这一步不会伤到宿主背景（图层隔离）。
3. **调色板插值**：光团颜色不是常量，而是沿噪声值在两个主色之间插值（CPU 端按团给色即可，
   不必逐像素），配合 4–5% alpha 的 dither 去色带。

性能预估（待实测）：

| 手法 | 全屏 pass 增加 | 备注 |
|---|---|---|
| 6–8 个软光团 | 约 0.5–1.5 屏面积 | 圆内填充 |
| 噪声切形 | +1 屏 | DST_IN 铺满，需硬件层 |
| dither 叠加 | +1 屏 | 可用 4×4 位图 + REPEAT，成本低 |
| 合计 | 约 2.5–3.5 屏/帧 | 30 fps 目标；先按 24 fps 起 |

## 4. 推荐顺序

1. **R2 先做**（不依赖音频、不依赖外部 App），用歌词 onset 驱动，先把"好看"这件事立住；
2. R2 稳定后，把能量源抽象成接口（`pulse(strength)` 已有），**R3 只替换数据源**；
3. R1 作为 R2 的"省电/低配"档保留（设置里可选"强度/风格"）。

## 6. R2 参数草案（拿到子代理的 shader 清单前先按经验值）

| 参数 | 草案值 | 说明 |
|---|---|---|
| 调色板 | 4 簇（k-means, HSV，64×64 输入） | 主色 0、辅色 1、暖白、深色用于阴影 |
| 光团数量 | 6（大 2 / 中 2 / 小 2） | 半径 0.34 / 0.22 / 0.13 × min(w,h) |
| 漂移 | 2D value-noise，频率 0.15–0.25 /s | 各自相位不同，避免"整齐呼吸" |
| 漂移幅度 | 屏宽 12–18% | 太大会晕，太小像静止 |
| 呼吸 | 20–40 s 周期，幅度 ±12% | 比现在的 7 s 慢很多 |
| 换行脉冲 | 全局 +55% 亮度，attack 90 ms，decay 900 ms | 比现在的 420 ms 更"慢燃" |
| 逐词脉冲 | 局部 +12%，decay 260 ms | 提供细节密度 |
| 噪声切形 | fBm 256×256，平移 0.02 屏/秒 | DST_IN，边缘不规则 |
| dither | 4×4 位图，alpha 4% | 去色带 |
| 目标帧率 | 24 fps（脉冲时 30） | 先测 jank 再定 |

## 7. 设置形态（建议替换掉现在的三项滑块）

```
词曲光效：  关闭 / 极简（边缘光） / 极光（默认）
  亮度     ————●————  0–150%
  速度     ——●——————  0.5×–2×
  （极光风格下才显示"范围"，极简风格沿用现在的"范围"）
```

理由：现在"强度/范围/呼吸"三项是**参数**，用户其实想选的是**风格**；保留两个通用参数即可。
迁移：现有三个 key 保留读取，新增 `lyric_glow_style`，老值映射到"极简"。

## 8. 风险清单

| 风险 | 缓解 |
|---|---|
| 大面积渐变出现色带 | dither 层 + 分段 stop |
| 多光团 PLUS 叠加过曝 | 总 alpha 归一化；用封面平均亮度自适应 |
| 宿主深色底图上"发灰" | 用 SCREEN 而非 PLUS；或在暗底时提高 saturation |
| 60 fps 掉帧 | 24 fps 起步；`gfxinfo` 守门；必要时降分辨率（画进 1/2 Bitmap 再拉伸） |
| 与歌词阴影/羽化打架 | 我们只在最底层画，不碰文字合成 |
| 旋转/切歌重挂载 | 复用现有 `attach/watcher` 逻辑 |
